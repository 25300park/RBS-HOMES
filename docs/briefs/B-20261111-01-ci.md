## 1. 목표

## 2. 범위 안
- .github/workflows/ci.yml 신규 작성
  - 트리거: pull_request(대상 main), workflow_dispatch
  - 같은 PR의 이전 실행은 취소한다 (concurrency)
  - permissions는 contents: read 하나만 둔다
  - 환경: ubuntu-latest, Node 버전은 배포 환경과 맞춘다 (사전 조사 결과로 결정)
  - 단계는 한 job으로 순서대로: npm ci, prisma generate, 타입체크(tsc --noEmit), 린트, 테스트(vitest), 빌드
  - .next와 tsconfig.tsbuildinfo는 캐시하지 않는다. npm 캐시만 허용한다.
  - 타임아웃 15분
  - job 이름은 verify, 워크플로 이름은 CI로 고정한다. (브랜치 보호에서 이 이름을 지정한다.)
- 빌드와 린트에 필요한 환경변수는 워크플로 파일 안에 가짜 값으로 직접 쓴다. 이름은 코드가 읽는 것만 쓴다. EMAIL_MODE는 off로 둔다.
- 운영 DB를 건드리지 않는다. DATABASE_URL은 존재하지 않는 가짜 주소다.
- docs/ci.md 신규 작성 (10~20줄): 무엇이 도는지, 로컬에서 같은 순서로 재현하는 법, vitest 4.x는 @types/node 20을 허용하므로 @types/node를 올릴 때 vitest 호환을 함께 확인한다는 메모
- docs/approval-policy.md 수정: 아래 네 줄을 추가한다.
  1. 에이전트는 PR을 머지하지 않는다. 머지는 대표만 한다.
  2. 필수 검사의 이름은 CI / verify다.
  3. 혼자 운영이므로 필수 승인 수는 0이고, 대표의 머지 클릭이 승인이다.
  4. 규칙 우회 머지는 예외에만 쓰고, 쓰면 PR에 사유를 남긴다.

## 10. 완료 보고 (에이전트가 채움)

**사전 조사 결과**:
1. **Node 버전**: `.nvmrc` 없음(node_modules 안에만 있는 무관한 파일), `package.json`에 `engines` 없음. `deploy.yml`은 `actions/setup-node` 같은 단계가 없고 EC2에 이미 설치된 Node로 그냥 `npm run build`를 돌림 — 배포 환경의 Node 버전을 파일에서 확인할 수 없었음. 가장 가까운 증거는 `devDependencies`의 `@types/node: "^20"` → **Node 20**으로 결정.
2. **scripts**: `build: "prisma generate && next build"`, `lint: "next lint"`, `test: "vitest run"`, `dev`/`start`/`seed` 있음. `postinstall` 스크립트 없음 — `prisma generate`는 `build` 스크립트 안에서만 돎(CI에서 별도 단계로 명시).
3. **기존 워크플로**: `.github/workflows/deploy.yml` 하나뿐. 트리거는 `push: branches: [main]`뿐이라 신규 `ci.yml`(`pull_request`, `workflow_dispatch`)과 트리거가 겹치지 않음.
4. **빌드의 DB 의존성**: 가짜 `DATABASE_URL`(`mysql://fakeuser:fakepass@fake-host-does-not-exist:3306/fakedb`)로 캐시 삭제 후 `npm run build` 로컬 시험 → **성공(exit 0)**. 빌드 로그에 두 곳이 내부적으로 에러를 잡고 넘어감: `app/sitemap.xml`이 `prisma.unit.findMany()` 호출 중 `PrismaClientInitializationError`(DB 연결 불가)를 캐치해서 로그만 남기고 계속 진행, `/api/google-reviews`가 가짜 구글 키로 `REQUEST_DENIED` 에러를 캐치해서 로그만 남기고 계속 진행. 빌드를 막는 수준의 DB 의존은 없음.
5. **빈 MySQL 마이그레이션 시험**: 로컬에 Docker Desktop이 설치되어 있으나 데몬이 꺼져 있어(`dockerDesktopLinuxEngine` 파이프 연결 실패) 컨테이너를 띄우지 못함. **미확인**.
6. **린트**: `npx next lint` exit code 0, warning 110건(전부 `@next/next/no-img-element`와 `react-hooks/exhaustive-deps`), error 0건.

- `.github/workflows/ci.yml` (신규)

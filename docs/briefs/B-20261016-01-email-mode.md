## 1. 목표
모든 이메일 발송이 EMAIL_MODE 값(off, redirect, live)에 따라 동작해서, 개발과 CI와 EC2에서 실제 사용자에게 메일이 나가지 않는다.

## 2. 범위 안
- 메일을 보내는 모든 진입점을 전수 조사한다.
- 모든 발송이 lib/email.ts의 sendEmail() 한 곳을 거치게 정리한다.
- sendEmail()에 모드 분기를 넣는다 (off / redirect / live).
- 로그에는 수신자를 마스킹해서 남긴다.
- .env.example에 EMAIL_MODE와 EMAIL_REDIRECT_TO를 설명과 함께 추가한다.
- 테스트 러너가 없으므로 Vitest를 최소 설정으로 추가한다.

## 3. 범위 밖
- 발송 장부, 하루 100통 카운터, 웹 푸시, 새 알림 추가, 메일 본문과 제목 변경
- Vercel과 EC2의 환경변수 값 설정
- 이 브리프에 없는 파일, 화면, 테이블 수정

## 5. 사전 조사 (읽기 전용) — 완료

검색: `resend|nodemailer|sendMail|emails\.send|sendEmail` (전체 .ts), `RESEND_API_KEY|new Resend`, `smtp|nodemailer|mailgun|sendgrid|@resend` (대소문자 무시)

- **Resend를 직접 호출하는 곳**: `lib/email.ts` 단 한 곳 (`resend.emails.send`, 5번째 줄에서 `new Resend(process.env.RESEND_API_KEY)`로 클라이언트 생성).
- **sendEmail()을 호출하는 진입점 3곳**, 전부 이미 `lib/email.ts`의 `sendEmail()`을 거침 (추가 통합 작업 불필요):
  1. `lib/action.ts:62` — `resetPassword()` server action, 비밀번호 재설정 메일. 주의: `prisma.$transaction` 콜백 내부에서 호출됨 (이 브리프 범위 밖, 손대지 않음).
  2. `app/api/pms/tour-action/route.ts:72` — 투어 요청 거절 메일.
  3. `app/api/pms/tour-action/route.ts:147` — 투어 요청 확정(승인) 메일.
- **message-action.ts / message-text.tsx**: 이메일 발송 없음 (사이트 내부 메시지/알림 전용, DB에만 기록).
- **사용 중인 이메일 관련 환경변수**: `RESEND_API_KEY` (lib/email.ts)뿐. `nodemailer`, `NEXT_PUBLIC_EMAIL_USER`, `NEXT_PUBLIC_EMAIL_APP_PASSWORD`(.env.example에 존재)는 코드에서 참조하는 곳이 없음 (죽은 설정으로 보이나 이 브리프 범위 밖, 손대지 않음).
- **결론**: 발송 함수가 이미 1개뿐이라 "통합" 작업은 불필요. `sendEmail()` 내부에 모드 분기만 추가하면 AC-1이 자동으로 충족됨.
- **테스트 러너**: package.json에 jest/vitest 등 없음 → Vitest 최소 설정 신규 추가 필요.

  - `5.0.0` ~ `5.1.0` (최신 5.x): `@types/node`: `^22.0.0 || >=24.0.0` — 20 미포함.

- **해결**: `package.json`의 `vitest`를 `^5.0.5` → `^4.1.12`로 변경, `npm install`로 `package-lock.json` 재생성 (`@types/node`는 그대로 `20.19.43`, `.npmrc`는 건드리지 않음).
